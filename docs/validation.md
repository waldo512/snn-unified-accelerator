# 05 验证边界与后续工作

本包已整理最终候选、已有实验与可复查结果。项目收尾、论文投稿和产品化是不同验收范围；本页用于防止在接手或写作时扩大证据结论。

## 已建立的证据

| 层级 | 已有内容 | 支持的判断 |
|---|---|---|
| 算法 | N-MNIST、SHD、DVS-Gesture 的 mask、扰动、重复 episode 与工作点实验 | 所选更新范围在已测协议下的收益/状态成本折中 |
| 定点/RTL | FC、SRNN 输出更新；SCNN classifier 真实数据更新；提交后前向可见性；学习关闭零写 | 已覆盖数值与事务边界内的正确性 |
| 统一控制 | FC→SRNN→SCNN→FC 无全局复位，owner/排空/状态隔离检查 | 一套阵列可按时间切换拓扑 |
| 硬件对照 | 固定外壳、学习开/关、共享/私有输出学习器 | 匹配条件下的资源收益和代价 |
| 物理实现 | RUN120 与 RUN122 全路由，15 ns OOC 核心 setup/hold 闭合 | 目标器件上内部核心的实现可行性 |

## 必须随结果保留的限制

- RUN120 WNS 只有 +0.075 ns，属于已闭合但裕量小的工作点。没有通过多布局种子实验证明稳定裕量。
- 外部 I/O 延迟未约束；OOC 时序结果不能写成板级全接口时序签核。
- 原始 DRC/methodology 普通警告仍在报告中，不能写成“所有警告为零”。
- 真实 SCNN B4×T4 学习测试从 classifier 特征边界开始；与全图前向证据结合，仍不能替代完整数据集、整图在线适应 RTL 精度。
- SRNN 主算法 support=128 的完整 episode 端到端硬件延迟仍缺直接测量。
- 算法平均增益的 ± 项为原报告定义的离散度，引用时需按 JSON 核对；不能自行改称置信区间。
- 私有输出学习器 RUN123 是综合资源对照，没有对应后布线等价性能结论。
- 无 bitstream、板卡测量、JTAG/VIO、实测功耗、实测能效和后仿真结论。

## 论文主张应收紧到哪里

可以主张：TP 派生的选择性在线适应与三拓扑共享物理推理底座相结合，通过限定可写状态和受控提交降低重复硬件投入，并在所列实验边界内验证功能与实现可行性。

不能直接主张：全网络所有层在线训练、全部学习算术共享、三拓扑同时并发、对所有已有方案全面领先、全局最优 mask、板级实时运行或顶刊顶会接收保证。

共享输出学习器的面积收益较小，综合 setup 裕量也低于私有对照，应完整报告。主要共享收益来自统一推理底座。

## 后续工作优先级

1. 投稿目标确定后，按论文真正主张决定是否补完整数据集 RTL 精度、完整 SRNN 窗口延迟或特定相关工作对照。不要为扩大表格而重做已有实验。
2. 若要声称端到端 SCNN 在线适应精度，补整图输入至更新后预测的同次真实数据验证，并检查与算法 profile 一致。
3. 若新增板级、功耗或实时接口主张，另行补 I/O 约束、硬件运行与测量方法。
4. 最后按目标 venue 整理图表、相关工作、正文和开源许可。当前 paper 目录只提供中文主线与文献条目。

最终版本变更后，先识别受影响的算法/RTL/物理证据，再有针对性地更新。本包中原始报告应继续保留，以便区分旧结果与新结果。
