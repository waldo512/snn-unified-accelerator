# 02 算法、架构与电路主线

## 1. 算法层：选择性在线适应

本项目借鉴 TP 的前向学习思想，但不是逐字复制参考论文的网络或硬件。核心做法是把在线适应拆成可观察、可量化的局部更新事务，并通过数据集消融决定哪些张量值得在 FPGA 上保持可写。

每个拓扑都遵循同一原则：

1. 从已有较好推理权重开始；
2. 在受控分布偏移或事件扰动下提供少量有标签 support；
3. 比较只更新不同参数集合时的适应增益、干净集保持、写次数和状态容量；
4. 选择收益稳定、状态最小的主 mask；
5. 将该 mask 的数值格式、残差、投票/误差信号和提交语义固化为 RTL 契约。

最终选择为 FC W2、SRNN Wout、SCNN classifier。更大 mask 分别需要 232.20 倍、23.50 倍和 105.73 倍可写状态，当前证据不足以支持把它们常驻在主硬件中。

## 2. 数值契约

| 拓扑 | 前向/观察数值 | 更新状态 | 主更新方式 |
|---|---|---|---|
| FC | INT8 前向码，UQ6.10 trace | Q0.15 residual + INT8 code | magnitude-residual，比例因子 11 |
| SRNN | 冻结循环骨干，M2 Wout 为 signed Q2.14 | Wout code/residual | direct-response，increment 31、threshold 65 |
| SCNN | Conv8 池化观察为 Q8.8 | Q0.15 classifier code/residual | fixed-SGD magnitude-residual，比例因子 640 |

三者共享事务概念和部分数据面，但数值域不同，因此不能为了形式统一强行把所有学习算术合成同一个模块。最终设计只在数值契约兼容处共享。

## 3. 微架构层：一套共享底座

数据流可以概括为：

```text
运行时 profile / descriptor
            |
      owner 与排空控制
            |
  一个 12xH40/P4 物理阵列
            |
共享工作集/状态/参数访问协议
            |
FC / SRNN / SCNN 轻量拓扑适配器
            |
观察、学习、RMW、版本发布
```

共享部分包括：

- H40 神经元状态更新和 trace 相关基础能力；
- P4 计算调度底座；
- owner、drain、commit 和版本控制；
- banked 工作集和可重寻址状态访问；
- 参数读改写协议与下一次前向可见性；
- FC/SCNN 兼容数值域下的输出学习服务。

只允许保留的拓扑适配器包括：

- FC：前馈 descriptor 调度、归约和 W2 观察；
- SRNN：循环源调度、前一时间步状态、骨干到 M2 的相位桥和独立 Wout 数值协调器；
- SCNN：空间/通道 wave 调度、feature workset、池化、Conv8 观察与 classifier 适配。

这种划分避免重新接近三套拓扑资源并集，同时承认不同数据依赖不可能全部由纯组合开关消除。

## 4. 电路层：关键实现机制

### 4.1 互斥 owner 与无全局复位切换

当前拓扑拥有阵列期间，其他拓扑客户端不能注入命令。切换前必须完成 drain，并清理局部 owner 状态。定向测试已覆盖 `FC -> SRNN -> SCNN -> FC`，返回 FC 时循环兼容状态保持惰性，不需要全局复位。

### 4.2 参数 RMW 与原子发布

学习路径不直接破坏前向正在读取的参数版本。贡献经过地址化调度后进入参数读改写，完成一个受控窗口后发布新版本，并通过 commit/detach 边界保证下一次前向看到完整的新状态。

### 4.3 输出学习器共享边界

FC 与 SCNN 的输出更新可以复用统一服务。RUN123 私有分支对照表明，共享版本在整机综合阶段节省 1,709 LUT、1,203 FF、3.5 BRAM36eq 和 7 DSP。SRNN 的 Q2.14/direct-response 契约不同，保留独立协调器。因此论文应写“兼容数值域内共享”，而不是“全部学习算术共享”。

### 4.4 存储和生命周期复用

逻辑层和拓扑按顺序执行，因此状态、feature workset、观察 replay 和参数窗口按生命周期复用，而不是为最大网络的所有中间特征永久并行常驻。最终主 mask 进一步削减了可写参数银行。

## 5. 从算法结果反向修改硬件的实例

- FC：消融显示 W0+W2 的可写状态为 W2-only 的 232.20 倍，因此主配置取消 W0 在线更新银行。
- SRNN：Wh1+Wout 的状态为 Wout-only 的 23.50 倍，因此主配置冻结 M2 的 Wh1，只更新 M2 输出层。700→450 循环骨干在这组实验中本来就是冻结特征提取器；不能把 Wh1 消融误写成骨干可训练性的消融。
- SCNN：Conv8+classifier 的状态为 classifier-only 的 105.73 倍，48 个匹配 episode 中没有带来足以覆盖成本的新增收益，因此 Conv8 只保留为可选能力/消融，不常驻主配置。
- 运行点：SRNN support=128、SCNN temporal window T=4 被写入主 profile，但作为工程折中而非全局最优声明。

这条“算法消融 -> 可写状态选择 -> 共享微架构 -> 物理实现”的因果链，是论文叙事的核心。
